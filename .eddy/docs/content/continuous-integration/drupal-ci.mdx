# Drupal.org CI

After your extension is [mirrored to Drupal.org](../deployment/README.mdx), Drupal.org can test it with its own GitLab CI, which runs when the repository has a `.gitlab-ci.yml`. Eddy doesn't ship that file, so you add it. Eddy's configuration works with GitLab CI apart from 1 setting, which this page shows. The PHPStan error suppressions work too, even though GitLab CI runs the analysis from within the module directory.

PHPUnit needs 1 override there: turn off code coverage. GitLab CI symlinks your project back into the built site's `web/modules/custom/<name>/` directory, so PHPUnit's coverage scan follows that loop into `web/core/node_modules` and runs out of file descriptors. GitHub Actions collects coverage already, so GitLab CI can skip it.

To set it up, create a `.gitlab-ci.yml` in your project root that includes the [standard Drupal.org GitLab CI templates](https://git.drupalcode.org/project/gitlab_templates), as their instructions show. Then add this override to the same file:

```yaml title=".gitlab-ci.yml"
variables:
  _PHPUNIT_EXTRA: '--no-coverage'
```

GitLab CI applies the patches declared in your extension's `composer.json` with composer-patches 1.x, and ignores the ones in `composer.dev.json`. So a patch that your tests need on GitLab CI too goes in `composer.json`. See [Patch dependencies](../development/dependencies.mdx#patch-dependencies) for what each file's patches reach.
