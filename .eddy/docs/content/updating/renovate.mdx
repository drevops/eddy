# Dependency updates

Eddy includes a [Renovate](https://docs.renovatebot.com/) configuration, `renovate.json`, that keeps the npm packages in `package.json`, and the GitHub Actions and Docker images in `.github/workflows/*.yml`, up to date. Install the [Renovate GitHub app](https://github.com/apps/renovate) on your repository to turn it on.

## What it does

- Minor and patch updates share 1 pull request on the `deps/all` branch, and major GitHub Actions updates share another on `deps/major-all`.
- Pull requests merge on their own once their checks pass. Renovate hands the merge to GitHub's auto-merge, which waits only for the checks that [branch protection](../continuous-integration/branch-protection.mdx) requires, so set that up before you rely on it.
- GitHub Actions and Docker images are pinned to SHA digests.
- Version ranges in `package.json` are bumped to the latest version, such as `^1.2` to `^1.3`.
- Once a week, Renovate rebuilds `package-lock.json` from scratch and opens a pull request on the `deps/lock-file-maintenance` branch when the result differs, so the packages that your npm packages depend on move to the newest releases their ranges allow. Bumping a version in `package.json` doesn't do that: it leaves them at the versions the lock file already holds, as long as those still fit.
- A Dependency Dashboard issue tracks pending updates, approval requests and detected problems.

## What it leaves to you

Renovate leaves Composer packages and major npm versions alone. Update the dependencies in `composer.json` by hand, to keep them compatible with Drupal.org packaging, and apply major npm updates by hand too. Every build resolves the `composer.dev.json` ranges to their newest releases anyway (see [How versions are resolved](../development/drupal-versions.mdx#how-versions-are-resolved)).

See the [Renovate documentation](https://docs.renovatebot.com/configuration-options/) for every option.
