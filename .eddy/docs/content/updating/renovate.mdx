# Dependency updates

Eddy includes a [Renovate](https://docs.renovatebot.com/) configuration, `renovate.json`, that keeps the GitHub Actions and Docker images in `.github/workflows/*.yml` up to date, and the npm packages in `package.json` within their major versions. Your extension gets it when you keep Renovate in the installer. To turn it on, install the [Renovate GitHub app](https://github.com/apps/renovate) on your repository. This page explains what Renovate does with this configuration, and what it leaves to you.

To add Renovate to an extension that left it out in the installer, copy [`renovate.json`](https://github.com/drevops/eddy/blob/main/renovate.json) from Eddy into the root of your project. Add a `renovate.json export-ignore` line to `.gitattributes` too, so the file stays out of the release archives that Drupal.org packages. Then install the app.

## What it does

With this configuration, Renovate works like this:

- Minor, patch and digest updates share 1 pull request on the `deps/all` branch. Major updates of GitHub Actions and Docker images share another on `deps/major-all`.
- Pull requests merge on their own after their checks pass. Renovate hands the merge to GitHub's auto-merge, which needs **Allow auto-merge** turned on in the repository's **Settings** → **General**. It waits only for the checks that [branch protection](../continuous-integration/branch-protection.mdx) requires, so set that up before you rely on it.
- GitHub Actions and Docker images are pinned to SHA digests.
- Version ranges in `package.json` are bumped to the newest minor or patch release, such as `^1.2` to `^1.3`.
- Once a week, Renovate rebuilds `package-lock.json` from scratch. When the result differs, it opens a pull request from the `deps/lock-file-maintenance` branch to your default branch, so the packages that your npm packages depend on move to the newest releases their ranges allow. Bumping a version in `package.json` doesn't do that: it leaves them at the versions the lock file already holds, as long as those still fit.
- A Dependency Dashboard issue tracks pending updates and detected problems.

## What it leaves to you

The configuration turns on only Renovate's npm and GitHub Actions managers, and the GitHub Actions manager covers the Docker images that the workflows use too. So Renovate leaves the Composer packages in `composer.json` and `composer.dev.json` alone. It also leaves the major versions of npm packages and the `node` and `yarn` versions of `package.json`, such as `engines.node`, alone. Update the dependencies in `composer.json` by hand, to keep them compatible with Drupal.org packaging, and apply major npm updates by hand too. Every build resolves the `composer.dev.json` ranges to their newest releases anyway (see [How versions are resolved](../development/drupal-versions.mdx#how-versions-are-resolved)).

See the [Renovate documentation](https://docs.renovatebot.com/configuration-options/) for every option.
