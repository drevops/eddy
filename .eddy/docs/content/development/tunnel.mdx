# Public tunnel

In a remote development environment, such as Codespaces, DevPod, a remote Docker host or an SSH dev box, the PHP webserver listens on the `localhost` of the remote machine, which your own browser can't reach. The [tooling](tooling.mdx) can expose it through a [Cloudflare quick tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/do-more-with-tunnels/trycloudflare/), a public `*.trycloudflare.com` HTTPS URL that needs no account, DNS or configuration. This page shows how to turn the tunnel on, what it changes and how to open the site on a phone.

:::warning Anyone with the URL can reach the site

While the tunnel is up, the site is on the public internet, and a local Drupal site usually has a known admin account and no firewall. Use disposable test data only, never real or sensitive content, and stop the tunnel with `stop` when you're done.

:::

## Turn on the tunnel

To turn on the tunnel:

1. Install [`cloudflared`](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/) so it's on your `PATH`.
2. Set `CLOUDFLARE_TUNNEL=1` in `.env` or in your shell.
3. Build the site. On a site you've already built, running `start` and then `provision` is enough.

The following commands set the variable in your shell, then build:

<CommandTabs
  make={`export CLOUDFLARE_TUNNEL=1
make build`}
  ahoy={`export CLOUDFLARE_TUNNEL=1
ahoy build`}
  none={`export CLOUDFLARE_TUNNEL=1
scripts/eddy-tooling
vendor/bin/eddy-assemble
vendor/bin/eddy-start
vendor/bin/eddy-provision`}
/>

Confirm that the tunnel is up: the build prints a `*.trycloudflare.com` address as the site URL, and `info` prints it too.

The tunnel stays off while `CLOUDFLARE_TUNNEL` is empty or unset in both your shell and `.env`, or set to `0`, `false`, `no` or `off` in any letter case. Any other value, such as `1`, turns it on. An empty value in your shell counts as unset, so to override a `.env` that turns the tunnel on, set `0`, `false`, `no` or `off` in your shell instead. For a single command, prefix it, such as `CLOUDFLARE_TUNNEL=0 make start`.

## What happens

The tunnel changes what these commands do:

- `start` starts a tunnel, or reuses a running one that forwards to the same port and whose URL still answers, and writes its URL to `.env` as `TUNNEL_URL`. Without `cloudflared`, or when no URL appears within 30 seconds, it carries on without the tunnel and says so.
- `provision` adds the reverse-proxy and trusted-host settings that Drupal needs behind the tunnel to `settings.php`.
- `start`, `provision`, `info`, `drush` and `login` use the tunnel URL as the site URL.
- `stop` closes the tunnel and removes its URL from `.env`, whatever `CLOUDFLARE_TUNNEL` holds. `assemble` and `reset` close it too.

Turning the variable off doesn't close a running tunnel: `start` leaves it running, and the site public, until the next `stop`. To close the tunnel, run the following command:

<CommandTabs
  make={`make stop`}
  ahoy={`ahoy stop`}
  none={`vendor/bin/eddy-stop`}
/>

`cloudflared` writes its output to `.logs/cloudflared.log` in the project root, which is the place to look when a tunnel doesn't come up.

## Bring your own tunnel

The commands treat any `TUNNEL_URL` in `.env` as the site URL, whichever tool wrote it. So a different tunnel, such as ngrok, can stand in when a [lifecycle script](lifecycle-scripts.mdx), such as `scripts/start-ngrok.sh`, starts it and writes its URL to `.env`. Keep `CLOUDFLARE_TUNNEL` off then, since the trusted-host settings it adds accept only the Cloudflare and local hosts. 2 things don't carry over:

- `provision` adds its settings for a Cloudflare tunnel only. Behind another tunnel, add the settings it needs to `settings.php` yourself, such as `reverse_proxy`, so Drupal detects HTTPS.
- `stop` removes only a `*.trycloudflare.com` URL from `.env`, so remove your tunnel's URL from a `stop-*.sh` script.

## Open the site on a phone

`vendor/bin/eddy-qrcode <url>` draws any URL as a QR code in the terminal, which is handy for opening a login link on a phone. It needs [`qrencode`](https://fukuchi.org/works/qrencode/) on `PATH`. To draw the site URL, run the following command:

```bash
vendor/bin/eddy-qrcode "$(vendor/bin/eddy-info site-url)"
```

To have `login` draw the one-time login link as a QR code too, set `LOGIN_QRCODE=1` in `.env` or your shell (see [Log in](provisioning.mdx#log-in)).
