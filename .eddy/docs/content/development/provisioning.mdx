# Provision the site

`provision` installs Drupal with your extension enabled on the codebase that [`assemble` built](building.mdx). It prints a one-time login link when it finishes. This page covers what `provision` does, where the database lives and how to run Drush and log in.

To get a clean site without reassembling the codebase, run `provision` on its own:

<CommandTabs
  make={`make provision`}
  ahoy={`ahoy provision`}
  none={`vendor/bin/eddy-provision`}
/>

## What it does

`provision` runs these steps in order:

1. Installs Drupal from the `standard` profile into a fresh SQLite database, with an `admin` account and no Update Status module. To install from another profile, set `DRUPAL_PROFILE` in your shell or `.env` to its machine name, such as `minimal` (see [Environment variables](environment-variables.mdx)).
2. Enables your extension, as a module or as a theme.
3. Rebuilds the caches.
4. Enables each `drupal/*` extension in the `suggest` section of your `composer.json`, as a module or as a theme (see [Optional dependencies](dependencies.mdx#optional-dependencies)).
5. Requests the front page once, so the caches are warm before you open the site.
6. Links Drupal's browser test output into `.logs/browser_output`, next to the other test artifacts.
7. Adds the reverse-proxy and trusted-host settings that a [public tunnel](tunnel.mdx) needs, when the tunnel is on.
8. Runs your `scripts/provision-*.sh` [lifecycle scripts](lifecycle-scripts.mdx).
9. Prints the site URL and a one-time login link.

## The database

The site keeps its data in an SQLite file at `/tmp/site_<extension>.sqlite`, where `<extension>` is your extension's machine name. Each provision starts the database from scratch. To look inside the file, open it with [DB Browser for SQLite](https://sqlitebrowser.org/).

## Run Drush

`drush` runs a Drush command against the site, with the site URL already set:

<CommandTabs
  make={`make drush status
make drush cr
make drush -- config:get system.site --format=json`}
  ahoy={`ahoy drush status
ahoy drush cr
ahoy drush config:get system.site --format=json`}
  none={`build/vendor/bin/drush -l "$(vendor/bin/eddy-info site-url)" status`}
/>

Ahoy passes the arguments through as they are. `make` reads its command line first, so follow these rules with `make drush`:

- Put `--` before the arguments when they include an option, since `make` reads an option as its own.
- An argument can't hold a space or name a `make` target, such as `help`, unless it's an option value joined with `=`.
- An option joined with `=` reaches Drush after the other arguments, whatever its position.
- A `NAME=value` word that isn't named like an option, such as `DEBUG=1`, stays a `make` variable and doesn't reach Drush.

## Log in

`login` prints a one-time login link for the `admin` account:

<CommandTabs
  make={`make login`}
  ahoy={`ahoy login`}
  none={`vendor/bin/eddy-login`}
/>

A one-time link stops working after it's opened. Drush 12 and 13 open the link in your browser unless `uli` gets `--no-browser`. `login` passes that option on those versions, so the link it prints still works. Drush 14 never opens a browser and rejects the option. When you run `drush uli` yourself on Drush 12 or 13, add `--no-browser` too.

To have `login` also draw the link as a QR code, set `LOGIN_QRCODE=1` in `.env` or your shell. The QR code helps you open the site on a phone over a [public tunnel](tunnel.mdx). The link that `provision` prints has no QR code. Any non-empty value turns the QR code on, `0` included. To turn it off, remove the variable from `.env` and your shell. The QR code needs [`qrencode`](https://fukuchi.org/works/qrencode/) on `PATH`, and without it `login` prints the link and then fails.
