# Provisioning

`provision` installs Drupal on the assembled codebase with your extension enabled, and prints a one-time login link when it finishes. Run it on its own to get a clean site without reassembling the codebase:

<CommandTabs
  make={`make provision`}
  ahoy={`ahoy provision`}
  none={`vendor/bin/eddy-provision`}
/>

## What it does

1. Installs Drupal from the `standard` profile into a fresh SQLite database, with an `admin` account and without the Update Status module. Set `DRUPAL_PROFILE` to install from another profile.
2. Enables your extension, as a module or as a theme.
3. Enables each `drupal/*` extension in the `suggest` section of your `composer.json`, as a module or as a theme (see [Optional dependencies](dependencies.mdx#optional-dependencies)).
4. Requests the front page once, so the caches are warm before you open the site.
5. Links Drupal's browser test output into `.logs/browser_output`, next to the other test artifacts.
6. Adds the reverse-proxy and trusted-host settings that a [public tunnel](tunnel.mdx) needs, when the tunnel is on.
7. Runs your `scripts/provision-*.sh` [lifecycle scripts](lifecycle-scripts.mdx).
8. Prints the site URL and a one-time login link.

## The database

The site keeps its data in an SQLite file at `/tmp/site_<extension>.sqlite`, named after your extension's machine name. Each provision starts it from scratch. [DB Browser for SQLite](https://sqlitebrowser.org/) can open it when you want to look inside.

## Running Drush

`drush` runs a Drush command against the site, with the site URL already set:

<CommandTabs
  make={`make drush status
make drush cr
make drush -- config:get system.site --format=json`}
  ahoy={`ahoy drush status
ahoy drush cr
ahoy drush config:get system.site --format=json`}
  none={`build/vendor/bin/drush -l "$(vendor/bin/eddy-info site-url)" status`}
/>

Put `--` before the arguments when they include an option, since `make` reads an option on its command line as its own. An argument can't hold a space or name a `make` target, such as `help`, unless it's an option value joined with `=`. Ahoy passes the arguments through as they are.

## Logging in

`login` prints a one-time login link for the `admin` account:

<CommandTabs
  make={`make login`}
  ahoy={`ahoy login`}
  none={`vendor/bin/eddy-login`}
/>

A one-time link stops working once it's been opened, and Drush 12 and 13 open it in your browser unless `uli` gets `--no-browser`. `login` passes that option on those versions, so the link it prints still works. Drush 14 never opens a browser, and rejects the option. When you run `drush uli` yourself on Drush 12 or 13, add `--no-browser` too.

Set `LOGIN_QRCODE=1` in `.env` or your shell to have `login` draw the link as a QR code too, which is handy for opening the site on a phone over a [public tunnel](tunnel.mdx). `login` only checks that the variable is set, so unset it to turn the QR code off rather than setting it to `0`. The QR code needs [`qrencode`](https://fukuchi.org/works/qrencode/) on `PATH`.
